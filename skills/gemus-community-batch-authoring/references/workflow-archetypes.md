# Workflow archetypes

Choose the archetype from the seed's dominant uncertainty and current portfolio coverage. Archetypes are reasoning shapes, not fixed node templates; vary node types, depth, branches, and deliverables inside each one.

A fixed PPT is a delivery contract, not an archetype. First decide how the case learns and makes decisions; then use the contract's narrative spine and evidence map to decide which results deserve pages.

| Archetype           | Use when                                                           | Characteristic shape                                              | Avoid                                          |
| ------------------- | ------------------------------------------------------------------ | ----------------------------------------------------------------- | ---------------------------------------------- |
| Evidence-first      | Core facts or references are uncertain                             | gather → compare → derive criteria → create                       | generic web research with no decision effect   |
| Journey-first       | Time, sequence, or handoff defines quality                         | moments/actors → pain points → interventions → test               | six identical storyboard panels for every case |
| Mechanism-first     | A behavior, interaction, or physical principle must work           | failure modes → mechanisms → prototype → verify                   | styling before feasibility                     |
| Constraint-first    | Space, brand, regulation, budget, or assets dominate               | constraints → feasible envelope → alternatives → compliance check | treating constraints as an appendix            |
| Branching-systems   | Audiences, channels, states, or conditions require different paths | classify → branch → specialize → reconcile                        | duplicating branches with only renamed prompts |
| Critique-loop       | Quality emerges through evaluation and revision                    | generate → score against rubric → diagnose → targeted revision    | an unbounded self-review loop                  |
| Variant-matrix      | Controlled exploration across independent dimensions is valuable   | define axes → sample combinations → compare → select              | random variants without explicit axes          |
| Ecosystem-synthesis | Multiple artifacts or stakeholders must form one coherent system   | parallel workstreams → shared rules → integration → handoff       | ending every workstream in one oversized deck  |

## Selection procedure

1. Name the decision that would still be hard if a polished image already existed.
2. Map that decision to the closest archetype.
3. Check the ledger report. When two archetypes fit, choose the underrepresented one.
4. Write one sentence explaining how the shape differs from the closest existing workflow.
5. Select deliverables that prove the desired outcome. Use PPT only when communication is itself an outcome.

## Structural novelty test

A workflow is not materially different when only its title, domain nouns, model, colors, or prompt wording changed. Material difference normally changes at least two of:

- information sources or evidence strategy;
- dependency graph, branching, or feedback path;
- decision rubric or evaluation stage;
- human role and interaction point;
- temporal structure;
- final artifact and validation method.

Across a batch, also vary the narrative spine, evidence types, visual grammar, and final decision object. Two graphs can be topologically different yet still feel homogeneous when they tell the same story with the same hero/angle/detail page sequence.
