# Seed brief contract

The source document is a collection of creative seeds, not a serialized workflow graph. Normalize every item before building it. Preserve author-specified invariants and deliberately reopen everything else.

## Fields

```yaml
id: stable batch-local identifier
title: working title
domain: PRODUCT | BRAND | SPACE | GAME | COMMERCE | OTHER
audience: who experiences or uses the result
context: situation, environment, and timing
tension: unresolved need, conflict, or opportunity
desired_outcome: observable change for the audience
dominant_uncertainty: evidence | journey | mechanism | constraints | branching | quality | variants | system
evidence_needed: what must be learned or supplied
candidate_deliverables: 1-3 outcome-shaped artifacts
fixed_constraints: facts the author explicitly requires
creative_freedom: choices Codex may invent
differentiation_axes: 2-4 meaningful portfolio dimensions
risks: safety, rights, cost, publishing, or factual risks
assumptions: additions made because the source was vague
```

## Expansion rules

- Infer audience, context, tension, and outcome when the input is vague; mark the additions under `assumptions`.
- Offer several candidate deliverables before selecting one. Do not assume a presentation is required just because prior workflows ended in PPT.
- Convert repeated stage lists into intent. “调研—分析—生成—汇报” does not require four fixed nodes.
- Keep explicit compliance, brand, source-asset, and platform constraints fixed.
- Prefer one strong differentiator that changes workflow logic over many decorative differentiators.
- Ask the user only when an inference changes safety, rights, material cost, audience, or external publication. Otherwise proceed with a reversible assumption.

## Batch-document guidance

A healthy Word planning document varies the problem, not the boilerplate. Each item can be short if it supplies a distinct audience, tension, dominant uncertainty, and outcome. Node recipes, fixed stage counts, universal output bundles, and identical wording should be omitted unless intentionally required.

Use a table with one row per seed if convenient. The minimum useful columns are: title, audience/context, tension, desired outcome, fixed constraints, and creative freedom.
